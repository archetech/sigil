# Sigil Traceability

A machine-checkable trace across four layers, so **any artifact can be explained by the need it serves, and any
need can be checked for coverage.** This replaces a manual spreadsheet: the source of truth is short tags
*co-located* in the artifacts, and the matrix ([`../TRACEABILITY.md`](../TRACEABILITY.md)) is *generated* from
them.

## The chain

```
foundational requirement (R*)  ←  feature requirement (XX-*)  ←  design point (D-*)  ←  code (@implements)  ←  test (@verifies)
```

An auditor asking *"why does this function exist?"* reads the function's `@implements` tag → the requirement →
the design point → the foundational need. The reverse — *"is this requirement covered?"* — is a column in the
matrix.

## Identifiers (stable, append-only, never reused)

| Layer | ID form | Where it lives |
|---|---|---|
| Foundational requirement | `R1`, `R2`, … | [`Requirements/sigil-v0-requirements.md`](../Requirements/sigil-v0-requirements.md) |
| Feature requirement | `<PREFIX>-<n>` (e.g. `AC-1`) | `Requirements/<feature>.md` |
| Design point | `D-<PREFIX>-<n>` (e.g. `D-AAC-3`) | tagged inline in `docs/<feature>.md` |
| Code | *(cites requirement/design IDs)* | `@implements` doc-comment on the function/module |
| Test | *(cites requirement/design IDs)* | `@verifies` doc-comment on the unit/e2e test |

Retire an ID if a point is removed; **never renumber or reuse**, so external references (commits, issues, audit
findings) stay valid.

## Tag syntax

- **Design point** — inline in a design note, at the head of the paragraph it names, with the requirement(s) it
  realizes after an arrow:
  `[D-AAC-3 → AC-3]` or, for several, `[D-AAC-8 → AC-8, R6]`.
- **Code** — a doc-comment on the function/module:
  `@implements AC-3` or `@implements AC-3, AC-6` (requirement or design-point IDs, comma-separated).
- **Test** — a doc-comment on the test:
  `@verifies AC-3` (unit or e2e).

A design-point ID cited by code/tests resolves to the requirement(s) it serves, so code may cite whichever is
most precise.

## The matrix

[`TRACEABILITY.md`](../TRACEABILITY.md) is generated by [`tools/trace/build-traceability.mjs`](../tools/trace/build-traceability.mjs)
— zero-dependency Node. Regenerate after any change to requirements, design, code, or tests:

```sh
node tools/trace/build-traceability.mjs
```

It scans `Requirements/`, `docs/`, and code/test files for IDs and tags and writes the matrix plus a **gaps
report** (requirements missing a design point, code, or test). **Do not edit `TRACEABILITY.md` by hand.**

## Rules

1. Every feature requirement SHOULD be realized by **≥1 design point, ≥1 code element, and ≥1 test** before it is
   "done"; the matrix flags each missing layer.
2. **A change to a design note updates its requirements and regenerates the matrix in the same commit** (see
   [`../Requirements/README.md`](../Requirements/README.md)).
3. When a function or test is written, it MUST carry an `@implements` / `@verifies` tag if it realizes or checks a
   requirement — this is what keeps the trace honest without a spreadsheet.
